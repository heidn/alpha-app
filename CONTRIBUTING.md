# Developer Guide

How the two of us build Alpha Strength together, with and without Claude Code.
Claude follows [CLAUDE.md](CLAUDE.md); this file is the human version of the same rules plus setup.

## 1. First-time setup

Prereqs: Node 22+ (LTS), Git, a Clerk account, a Convex account.

```bash
git clone https://github.com/heidn/alpha-app.git && cd alpha-app
npm ci
cp .env.example .env.local
```

**Convex (your own dev deployment — never share one):**
1. `npm run dev:backend` → log in, choose *create a new project* the first time (or your own dev deployment of the shared project).
   This writes `CONVEX_DEPLOYMENT` and `VITE_CONVEX_URL` into `.env.local` and generates `convex/_generated/`.
2. Leave it running; it pushes `convex/` changes to your dev deployment on save.

**Clerk:**
1. Use the shared Clerk *development* instance (ask the other dev for access) or create your own.
2. Copy the publishable key (`pk_test_…`, Clerk → **API Keys**) into `.env.local` as `VITE_CLERK_PUBLISHABLE_KEY`.
3. Open https://dashboard.clerk.com/apps/setup/convex → **Activate Convex integration**. Copy the **Frontend API URL** it shows
   (dev format: `https://verb-noun-00.clerk.accounts.dev`). No JWT template or webhook needed.
4. Set it on your Convex deployment:
   `npx convex env set CLERK_FRONTEND_API_URL https://<your>.clerk.accounts.dev`

**Run the app:** in a second terminal, `npm run dev` → http://localhost:5173. Sign up, then you should see "Signed in as …".
Your `users` row is created on first sign-in (`api.users.store`); check Convex dashboard → **Data → users**.
Stuck on "Loading…"? Check Convex dashboard → **Logs** (usually `CLERK_FRONTEND_API_URL` missing/wrong — no trailing slash).

**Optional:** `export CLAUDE_DEV=<your-short-name>` in your shell profile so memory notes and branch names are consistent. Otherwise `git config user.name` is used.

## 2. Daily workflow

1. `git fetch && git switch main && git pull`
2. One task = one branch = one worktree:
   `git worktree add ../alpha-app-<topic> -b <you>/<topic>` then open that folder (run `npm ci` there).
3. Post in Slack: what you're starting and which files you expect to touch.
4. Work, keep the PR small (< 400 lines). Rebase on `origin/main` before opening the PR.
5. Before the PR: `npm run typecheck`, `npm run lint`, and `npm audit --omit=dev` if you touched dependencies.
6. Squash-merge. Remove the worktree: `git worktree remove ../alpha-app-<topic>`.

Never commit directly to `main`. Never run `npx convex deploy` from a dev machine without agreeing in Slack first.

## 3. Avoiding collisions

**Hot files** — change in small, separate commits and announce in Slack:
`convex/schema.ts`, `convex/auth.config.ts`, `convex/http.ts` (if added), `src/main.tsx`, `src/App.tsx` / router, `package.json`, `package-lock.json`, `.env*`, `CLAUDE.md`, `.claude/settings.json`.

- Add new files instead of growing shared ones: backend `convex/<domain>.ts`, frontend `src/features/<feature>/`.
- **Schema changes are additive only:** add the field as `v.optional(...)`, backfill, then make it required in a later PR.
- Lockfile or `convex/_generated` conflict? Don't hand-merge. Take `main`'s version, then `npm install` / `npx convex dev --once`.
- Dependency upgrades go in their own `chore/deps-*` PR, never mixed with features.

## 4. Working with Claude Code

- At session start a hook (`.claude/hooks/start.sh`) shows Claude the shared memory and **which files the other dev's branches are changing**. If there's overlap, Claude will stop and ask.
- Claude keeps memory in `.claude/memory/` — this is committed and shared:
  - `STATE.md` — current architecture/decisions (short; you can edit it too).
  - `LOG.md` — one line per notable change/gotcha. Append-only; git union-merges it.
  - `dev/<you>.md` — your personal in-progress notes. Don't edit the other dev's file.
- Start Claude **inside your worktree**, not on `main` (the hook warns if you're on main).
- Claude is blocked from `convex deploy`, `npm audit fix --force`, and reading `.env` files (`.claude/settings.json`). Personal overrides go in `.claude/settings.local.json` (gitignored).
- If the Slack MCP isn't connected, Claude prints a one-line Slack message for you to paste.
- When a session gets long, ask Claude to update its dev notes, then `/compact` or start fresh.

## 5. Secrets

Never commit `.env.local` or paste keys into Slack, PRs, or Claude. Client-safe values use the `VITE_` prefix;
everything else lives in the Convex dashboard (`npx convex env set`). If a secret leaks, rotate it in Clerk/Convex immediately and tell the other dev.

## 6. Project layout

```
convex/            backend (schema, one file per domain)
convex/_generated/ generated by `convex dev` — never edit
src/main.tsx       providers (Clerk → Convex)
src/App.tsx        top-level auth gating
src/features/      one folder per feature
.claude/           Claude hooks, settings, shared memory
prompts/           source prompts used to generate repo instructions
```
